# Claude Eyes

macOS app (Swift, AppKit + SwiftUI, no Xcode project) showing robot eyes that react to the state of every running Claude Code session: one generated robot per session walking on the screens, an animated Dock icon (most important session + badge for sessions waiting for input) and a static menu bar icon (session list, settings).

## Data flow

```
Claude Code hook events ─▶ ~/.claude/hooks/claude-state.sh ─▶ ~/.claude/eyes/sessions/<session_id>.json ◀─ app watches the folder
```

- The hook source is `hooks/claude-state.sh`; `hooks/install.sh` symlinks `~/.claude/hooks/claude-state.sh` to it (`--copy`: copies it instead, what the app does with the hook it ships) and registers it on 15 events in `~/.claude/settings.json` (idempotent, writes through a linked `settings.json`, untouched when nothing changes, else backup `settings.json.bak-claude-eyes`, sets `terminalProgressBarEnabled: false`). The hook also drives Ghostty's tab progress bar (OSC 9;4) with a keepalive loop (Ghostty hides the bar after 15s without update). The loop stops 4s after `done` or after 30 min without event, never while `waiting` (the orange bar stays until the user answers).
- JSON fields: `sessionId, cwd, pid, tty, state, event, tool, command, signal, terminalApp, at, stateSince`.
  - `state`: `idle | working | toolError | waiting | done | failed` (file removed on `SessionEnd`).
  - `signal`: what a `PostToolUse` revealed: `testsFailed | testsPassed` (summary lines of PHPUnit, Pest, Jest, Vitest, pytest, RSpec, Mocha, go test, cargo test, swift test), `errorOutput` (well-known error formats: Python traceback, `fatal:`, compiler errors, JS/PHP errors, panics, `command not found`, npm), `bigEdit` (Write > 150 lines, Edit > 60 lines). Only the last 8000 characters of a command's output are searched; jq anchors `^`/`$` to the whole text, hence the `(?m)` prefix.
- Subagents: `SubagentStart`/`SubagentStop` (both carry `agent_id`, `agent_type`) keep `<session_id>.agents`, one line `<agent id> <start> <type>` per running subagent (renamed into place, removed when empty, on `SessionStart`/`SessionEnd`, and by the app when its `.json` is gone). `SubagentStop` changes nothing else. Entries older than 45 min are dropped: an interrupted subagent may never report its end. Subagents' own tool events carry their `agent_id` too.
- The app drops sessions whose `pid` is dead.

## Sources

- `Face.swift`: `Mood` (14 expressions, colors, labels), `EyeParams`/`FaceParams`, `FaceAnimator` (easing, blinks, gaze styles, bounces), `FaceRenderer.eyesPath` (single geometry source, lids carved with `CGPath.subtracting`), `FaceLayer` (GPU rendering, glow = CA shadow), app/menu icons, offscreen `Snapshot`.
- Performance: never draw the glow with a CPU shadow at 30 fps (it cost ~35% CPU). Robots, lab and settings previews use `FaceLayer`; the Dock tile is CPU-drawn but skips frames where `FaceFrame.isClose(to:)` (~5% CPU total).
- `Sessions.swift`: `SessionRecord` (JSON), `Session` (mood/priority/French status text derived from state + event + tool + elapsed time, `agents` from the `.agents` file, `prop` = the tool its robot holds while a `PreToolUse` runs), `SessionStore`, `ProjectRoot` (closest folder with a `.git`, cached: sessions sharing one form a robot team).
- Live status: Claude Code writes `status` (`busy | idle | waiting`), `waitingFor` and `statusUpdatedAt` (ms) to its registry `~/.claude/sessions/<pid>.json` whenever its UI changes. `Session.state` (and the hook's `resolveState`) correct the hook state with it: a dialog waiting for the user wins over hook events from subagents or parallel tools, and a `waiting` hook state followed by a later `busy`/`idle` means the user answered (no hook fires then). `waitingFor: "dialog open"` is a dialog the user opened (`/config`…), not Claude waiting.
- `Robot.swift`: robot generator. `RobotGenome` = every varying part (locomotion, body, head, neck, top, sides, arms, chest, sizes, colors, speed, restlessness) drawn from a seed by `SeededRandom` (SplitMix64); a session's seed is `UInt64(stableHash:)` (FNV-1a) of its id, or the one stored in `robotSeeds` after « Nouveau robot ». `RobotRig` builds the `CAShapeLayer` tree once (pivot groups with tiny bounds centered on their origin, so they rotate around it; layers: canvas → shadow, `mount` (orientation ±π/2 for climbing, beam scale/fade) → `bot` (facing flip, animated turn) → `hopper` (hops) → `torso` → `head` + `FaceLayer`). Motions (`idle | walk | cheer | sleep | fall | sit | dizzy | knock`, and for climbs `fly | hang | aim | climb | bounce`; `sit` lowers the hopper by `sitDrop`, legs dangling below the edge; `setMotion(_:force:)` restarts the loops after an `armPose` change: `hold` raises the right arm, `typing` taps both) are repeating CA animations capped at 24 fps, run by the render server; idle is still apart from one-shot `fidget()`, `wave()`, `celebrate()` and `emote(_:side:)` (a bubble on the canvas root, so not mirrored, as wide as its text: `toc`). Body and head get a light-from-above gradient (`shading`: bitmap drawn once, clipped to the path, so `render(in:)` sheets show it too, unlike a mask). Fixed canvas 140×140, foot at (70, 10); `extent` = drawn bounds in foot coordinates.
- `RobotWorld.swift`: screens (AppKit coordinates) and windows from `CGWindowListCopyWindowInfo` (layer 0, other apps, bounds only, no permission; CG y is flipped from the main screen's top). Surfaces: each screen's ground (`visibleFrame.minY`) and window tops with room above (below `visibleFrame.maxY`, minus the x ranges of windows in front). Walls: window sides reaching down to the surface with a free top at that corner (`Wall.side` ±1), or a window's face (`side` 0, `faces(from:)`: a top with room right above the surface; a window floating higher is only for fly/grapple). Horizontal neighbor screens share a ground only without a side Dock.
- `RobotCrew.swift`: `RobotCrew` (one `RobotAgent` per session, a sleeping mascot when none unless hidden, spawn/leave by beaming, 30 Hz timer stopped when hidden or screens asleep, one CA transaction per tick, window list read only while a robot is perched, climbing or falling, at most every 0.25 s, outfit checked every minute, teams recomputed on every session change). `RobotAgent` state machine: idle → decide (rest, visit or chase another robot, join a teammate, walk, climb a window side or face, sit on a window's edge, jump off a window, cross or beam to another screen; teammates on its surface keep it from leaving) by restlessness and mood (working moods move less, sleepy sleeps, happy celebrates). Waiting: knocks (`knock` state, a `toc` every `RobotRig.knockPeriod`) next to a side of its terminal's frontmost window (host app from `TerminalFocus.hostApp`, windows matched by owner pid) when that window is on the pointer's screen and comes down to the ground, in front of it otherwise; no such window: walks or beams to the pointer and cheers. Reactions: confetti when the mood turns happy on `testsPassed`, sparks when it turns to an error. Pointer: eyes follow it within 260 pt (`FaceAnimator.lookAt`, mirrored with `facing`); slow moves over the robot add up to a petting (hearts, wiggle, happy face for 2 s; a move faster than 900 pt/s resets it); 4 direction reversals within 1.2 s while carried make it dizzy (`FaceFrame.dizzy` spiral eyes, stars, `dizzy` state after landing). Its tool comes from `Session.prop`, kept 1.5 s between two tools, shown only while standing awake. Subagents: one `MiniBot` per running subagent (at most 6) in a layer under the robot, hidden inside it while it isn't standing. The stage has 60 pt of headroom for bursts and 34 pt below the foot for dangling legs. Its `RobotPanel` is a stage covering the whole surface it walks on: a walk is one CA position animation inside it, the window only moves on surface changes, falls and drags; climbing uses a square stage around the wall. `RobotPanel` overrides `constrainFrameRect`: when ordered front, AppKit pushes a window overlapping the menu bar below it, and the ground stage of a screen above the main one hangs 10 pt over that bar (its robot then drew outside its window). Clicks: `ignoresMouseEvents` follows whether the pointer is over the robot's bounds (transparent parts let clicks through). `RobotBubble`: title + status above the robot on hover, while waiting and for 4 s after its session changes state (`Session.state`, checked with the mood at 5 Hz).
- `RobotGear.swift` (extension of `RobotRig`, layers built on demand; gear animations use `gearLoop`, keyed `gear.*`, so motion changes keep them): `RobotProp` (magnifier, keyboard, wrench, test tube; cartoon-sized ×1.7, upright in the raised hand, floating beside robots without arms, the keyboard in front of the body), `burst(_:)` one-shot `confetti | sparks | hearts` (pieces on the canvas root, removed after their animation group), `setStars` (dizzy orbit), `RobotOutfit` (`at(date)`: pumpkin Oct 24–Nov 1, Santa hat Dec 1–26, beanie until February, headlamp 20 h–6 h), `setTeam` (a pennant on a pole behind the head, in `RobotTeam.color` with `RobotTeam.initial`, the repository's first letter drawn as a glyph path; `teamLetter` is flipped back with `facing` so it reads the right way), `highFive(side:clap:)` (raised arm, or a bump without arms; clap: a star where the hands meet), `MiniBot` (a subagent: the parent's genome at 0.42 scale, pops out of it, runs around within the surface, runs back and shrinks into it when its subagent ends).
- `RobotClimb.swift`: `ClimbStyle` (`crawl` turned sideways up a side, `fly`, `bounce`, `hands`, `grapple` with a rope from the body to a hook on the top edge); `RobotGenome.climbStyles` derives them from the parts (no seed draw, so existing robots keep their look), one picked at random per climb. `Ascent` = a climb as a pure function of time (`pose(at:wallX:top:)` → foot, motion, orientation, rope, done), recomputed from the window's current frame every tick and shared by the agent and the lab. A window that comes in front of the one a robot stands on is climbed by its face when it has room on top (`climbCover`), otherwise the robot falls.
- Encounters (`RobotCrew` "Robots together"): every 0.5 s free robots close on the same surface greet (face each other, wave or cheer, `RobotRig.emote` bubble next to the head: ! ? ♥ ♪ z); `decide` may visit a companion (asleep: ? and z) or start a chase (runner flees to the surface's end at 1.5× pace, chaser at 2.1×, tag on contact); a happy turn makes nearby robots cheer along. Per-robot cooldown `socialAt` (25–60 s). Waiting or sleepy sessions don't socialize. Teams (`RobotCrew.updateTeams`: sessions sharing a `ProjectRoot`, 2 or more): teammates meeting high-five (`Gesture.highFive`, at the same time, one shows the clap); a robot walking somewhere (`decide`, plain walk) is followed in a line by its free teammates on that surface within 500 pt (`RobotCrew.lead` → `follow`, which then greets the one ahead); 40% of `decide`s walk or beam to a teammate, and a teammate on its surface keeps it from leaving.
- `RobotLab.swift`: `--render-robots` sheet and the robot lab window (menu bar « Labo des robots… », `--robot-lab [step]`, e.g. `grimpe` or `se saluent` to start there): motions, climbs against a mock window (side and face, every style the robot knows), a round of hellos, tools, bursts, dizzy, sitting, knocking, outfits, team pennants and high fives (teammates in neighboring cells, at their shared border) and subagents (`outils`, `effets`, `vertige`, `assis`, `toque`, `saisons`, `équipes`, `sous-agents`); its timer runs only while it is open. Interactive: a bar (step, « Enchaîner les étapes », mood and eye color overrides, new robots; ←/→, space, R through a local key monitor) and robots that follow the pointer, get petted, react to clicks (a different show each time), walk to a clicked spot, can be picked up, shaken (dizzy) and thrown; right click: new robot, keep it (« Nouveaux robots » spares it), copy or choose a seed. Each cell's `Bot` has a `Hand` (step, carried, falling, dizzy, walk, rest, beam out/in): only robots in `.step` follow the step; `dressUp`/`undress` put the step's gear on every robot, `pose`/`unpose` its motion, and `rejoin` walks (same floor) or beams to the step's `spot` first. After a climb a robot jumps off and walks back to the next climb's base. `ShakeMeter`, `PetMeter`, `RobotRig.gaze` and `RobotRig.bounds` (end of `RobotCrew.swift`) are shared with the desktop robots.
- `DockAndMenus.swift`: `DockTileController` (one face per Dock icon, 10 fps, skips still frames, badge), shared menu builder (menu bar + Dock), `StatusMenuController`.
- `DockPerSession.swift`: "one Dock icon per session" mode. A Dock icon = one process, so `DockHelperManager` launches the same binary once per session (`--dock-session <id> --parent <pid>`) from a per-session bundle copy in `~/Library/Application Support/Claude Eyes/Docks/<title>.app` (own `CFBundleName` so the Dock shows the session title, re-signed ad hoc, rebuilt when the main binary is newer, folder wiped at launch). Helpers (`SessionDockDelegate`) quit when their session or the main app disappears, and ask the main app to focus the terminal through a distributed notification (so only the main app needs the Ghostty Automation permission). Helpers read the main app's defaults through `UserDefaults(suiteName:)`. In this mode the main app has no Dock icon (menu bar only).
- `SessionLook.swift`: session title (`/rename`) and color (`/color`). Title from Claude Code's live registry `~/.claude/sessions/<pid>.json` (`name` when `nameSource != "derived"`), else the transcript's last `custom-title` entry. Color from the transcript's last `agent-color` entry (`TranscriptScan` reads only appended bytes after the first pass). `SessionColor` holds Claude Code's palette; calm moods draw the eyes in its light variant (`eyeComponents`), alert moods (`Mood.isAlert`: waiting, sad, annoyed, failed, happy) keep their own color and pulse towards white when the session has a color, so an orange session waiting for input stays recognizable. Tiles and robot screens stay dark. Per-session Dock helpers are named after the title and relaunched on rename.
- `SessionStore` watches the sessions directory (DispatchSource, the hook writes temp file + rename), each live registry file (Claude Code rewrites them in place, invisible to a directory watcher) plus a 2s timer for dead pids and the process scan; Dock helpers track only their own pid (`start(trackingPid:)`).
- `TerminalFocus.swift`: click on a session = bring back its terminal. Host app = closest regular-app ancestor of the claude pid (parent pids through `sysctl`, `proc_pidinfo` fails on root-owned `login`), else the hook's `terminalApp` (`__CFBundleIdentifier`, covers tmux). Terminal and iTerm2: AppleScript matching the tab/session `tty`; WezTerm: `wezterm cli list` + `activate-pane`; Ghostty: `GhosttyFocus`; anything else: activate the app.
- `Ghostty.swift`: `GhosttyFocus`, through Ghostty's AppleScript API (JXA via `osascript`); Ghostty doesn't expose ttys, so the terminal is identified by temporarily setting a unique title on the session's tty, then restoring it.
- Hook progress bar: only `TERM_PROGRAM` ghostty ≥ 1.2.0 and iTerm.app ≥ 3.6.6, the same rule as Claude Code's own bar (elsewhere OSC 9 may be shown as a notification). Setting "Barre de progression" off = the app creates `~/.claude/eyes/progress-disabled`; the hook then sends nothing and running keepalive loops clear the bar and exit. `ClaudeSettings.swift` hands the bar over to Claude Code: with ours off it removes `terminalProgressBarEnabled: false` from `~/.claude/settings.json` (Claude Code falls back to its own setting, on by default), with ours on it sets it back to false. Only when the hook is registered there; minimal text edit (formatting and key order kept), applied only if the result parses back as asked; symlink and permissions preserved. The keepalive loop forks nothing per second: registry read with `read -d ''` + `[[ =~ ]]`, clock from `SECONDS`, one-second wait = `read -t 1` on a FIFO nobody writes to (fd 9), so the bar turns orange or back as soon as a dialog opens or is answered.
- `Sounds.swift`: robot chirps (`Chirp`: waiting, done, failed) synthesized as WAV at runtime, played by the main app on state transitions (not during the first 3s, at most one per session every 2s, the most urgent when several sessions change). Per-session mute = `mutedSessions` in the shared defaults (ids `pid-<pid>`, pruned at launch), toggled from the menu bar, a robot's right-click menu or a session's Dock menu. Global mute = `muteAll` (menu bar / Dock menu item « Couper le son »), checked only when a chirp is about to play so state tracking keeps going.
- `Updates.swift`: `AppVersion` (numeric compare, `v` prefix), `Updater` (GitHub `releases/latest`, overridable with the defaults key `updateFeedURL` for tests; 20 s after launch then hourly once a day has passed since the last successful check, `Prefs.checkUpdates`; an unasked offer is shown once per version (`updateOfferedVersion`), then stays in the menus and settings; install: refuses a translocated or non-writable app, downloads `ClaudeEyes-*.zip` and its `.sha256`, checks the hash, unzips with `ditto` into an `itemReplacementDirectory` on the app's volume, checks bundle id, version and `codesign --verify`, then a detached bash script waits for the pid, swaps the bundles (puts the old one back on failure) and reopens it with `--updated-from <old version>`: robots throw confetti, or an alert says the old version stayed). `HookSetup`: the hook shipped in `Contents/Resources/hooks` (copied there by `build.sh`); status `missing | linked | installed(current:)`; at launch an outdated copy is refreshed with `install.sh --copy` (PATH plus Homebrew for jq), a link to a clone is left alone except after an in-app update when it differs (`contentsEqual` compares a link itself: resolve it first); missing: offered once per launch (« Ne plus demander » = `hookOfferDeclined`) and in the menus; after an install `ClaudeSettings.syncProgressBar` restores the bar setting.
- `Settings.swift`: `Prefs` (UserDefaults), SwiftUI settings window with a live expressions gallery, launch at login (`SMAppService`).
- `main.swift`: `AppDelegate` (launch: hook refresh, updater, `--updated-from <version>` after an in-app update), helper mode `--dock-session`, CLI modes `--render-iconset <dir>`, `--render-gallery <file.png>`, `--render-color-tiles <file.png>`, `--render-sounds <dir>`, `--render-robots <file.png>`, `--robot-lab [step]`.
- `docs/`: README images rendered with the CLI modes (`expressions.png`, `colors.png`, `icon.png`, `robots.png`). README in English (`README.md`) and French (`README.fr.md`): keep both in sync.
- `CHANGELOG.md`: one short entry per change set under `Unreleased`.

## Build

```bash
./build.sh            # build/Claude Eyes.app
./build.sh --install  # copy to ~/Applications and relaunch
./build.sh --zip      # also build/ClaudeEyes-<version>.zip + .sha256, the release assets
"build/Claude Eyes.app/Contents/MacOS/ClaudeEyes" --render-gallery build/gallery.png  # check expressions visually
```

Compiled with `swiftc -swift-version 5` (Swift 6 strict concurrency not enabled), target macOS 14, arm64, ad-hoc signed.

Releases: the `Release X.Y` commit and its annotated tag `vX.Y` are pushed as usual; on GitHub the tag runs `.github/workflows/release.yml` (macOS runner): it fails if the tag doesn't match `Info.plist`, runs `./build.sh --zip` and creates a **draft** release with the zip, its `.sha256` and notes made from the version's CHANGELOG section plus install steps. Edit the notes (one-line intro, bold lead per bullet: the update alert shows those leads), then publish: the in-app updater only sees published releases. A tag with a suffix (`v1.3-test1`) makes a draft prerelease to try the pipeline; a manual run (`gh workflow run release.yml -R AnselmeSDR/ClaudeEyes`) only builds the zip as a workflow artifact.
